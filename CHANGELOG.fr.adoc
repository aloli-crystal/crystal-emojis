== v0.2.0 — 2026-04-26

**Repo renommé et shards fusionnés.** Ce qui s'appelait
`crystal-emojis-lite` est maintenant `crystal-emojis` ; ce qui
s'appelait `crystal-emojis-full` est en cours de suppression, sa
fonctionnalité repliée dans ce seul shard via le nouveau cache
disque.

=== Ajouts

* **Module `CrystalEmojis::Cache`** — extension disque du set
  curé embarqué. Chaîne de lookup : set embarqué d'abord, puis
  cache. Permet une couverture Twemoji complète (~4000 SVG) sans
  gonfler les binaires dépendants.
* **API `Cache.pull(source:, system:)`** — déclenchement
  programmatique du téléchargement. Les apps peuvent peupler le
  cache depuis leur propre code Crystal (pas de dépendance CLI),
  configurer l'URL source (miroirs privés) et la cible (cache
  `user` vs `system`).
* **`Cache.dir`, `Cache.size`, `Cache.populated?`** — inspection.
* **CLI `bin/crystal-emojis`** avec sous-commandes `pull`, `info`,
  `purge` et drapeaux courts/longs `-s/--source`, `--system`,
  `-v/--version`, `-h/--help`.
* **Support des miroirs privés** — `pull --source URL` permet de
  pointer vers un NAS privé / Nexus / bucket S3. Les miroirs
  doivent fournir un `MANIFEST.txt` listant les codepoints ; le
  repo Twemoji amont est auto-découvert via l'API tree GitHub.
* **Chemin XDG conventionnel** avec variante macOS + override
  `--system` + variable d'env `CRYSTAL_EMOJIS_CACHE_DIR`.

=== Modifications

* `crystal-emojis-lite` → `crystal-emojis` (repo GitHub renommé).
* `CrystalEmojis.svg` retombe désormais sur le cache après le set
  embarqué — même signature, couverture plus large.

=== Dépréciations / suppressions

* Le shard `crystal-emojis-full` est en cours de suppression.
  Utiliser ce shard avec `crystal-emojis pull` à la place.

=== Migration depuis v0.1

Dans votre `shard.yml` :

[source,yaml]
----
# Avant
crystal-emojis-lite:
  github: aloli-crystal/crystal-emojis-lite

# Après
crystal-emojis:
  github: aloli-crystal/crystal-emojis
  version: "~> 0.2"
----

L'API Crystal est inchangée (nom de module `CrystalEmojis`).
